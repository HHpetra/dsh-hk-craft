# 关闭窗格不因中断被拒而困住用户

关闭运行中的窗格会先请求宿主中断当前回合，而宿主可以拒绝（`session/not-found`：没有挂载的 Agent；`session/agent-busy`：身份归子代理路由）或干脆不应答。旧实现把任何拒绝都当成致命错误：保留窗格并让全屏确认框一直开着、忙碌态不复位，于是所有其它窗格都点不动——用户只能等会话自己停下。现在把“中断”当成尽力而为的请求：宿主说没有回合可停就直接关；其它拒绝或超时清掉忙碌态、显示原因，并提供“仍然关闭”（释放窗格、回合留在后台，可在侧栏停止），Esc 与点击背景同样能退出。理由是释放窗格本来就只销毁客户端引用、不会停宿主的 Agent，所以“关不掉”不比“用户已知情地放弃中断”更安全。
