# 工作区管理与窗格工具栏补全

**Status:** ready-for-agent
**最后更新:** 2026-10-30

本 spec 覆盖四件事：侧栏工作区四态灯、删除与拖动排序、两个临时按钮迁入 HK Craft 设置页、窗格条工具栏补回“当前模式 + 子代理查看”并把新增会话按钮改为紧贴标签。**右侧边栏按钮本版不做**（上游约束见“实现决策”与“不做的事”）。

---

## Problem Statement

分屏用户现在看到的问题，从使用者的角度：

1. **侧栏灯色不可信。** 从来没在分屏里用过的空工作区也亮绿灯，看不出哪些工作区真正启用过；“绿灯”也没区分“只是没有会话在跑”和“真的有一段对话结束了”。
2. **侧栏少了原生有的工作区管理。** 工作区不能删除，也不能拖动排序。插件接管 `sidebar.workspaces` 后，这两个原生能力一起丢了；而删除又必须让用户明白“删的是工作区登记，不是目录和会话”。
3. **两个临时按钮占着侧栏底栏。** 诊断按钮和分屏切换按钮是开发期验证用的，却常驻侧栏 footer；用户希望它们收进设置里，并且 HK Craft 有自己的设置页。
4. **分屏后原生对话头部消失，工具也跟着消失。** 窗格只渲染对话内容，不挂原生 session header，于是“当前会话用的模式”和“子代理查看”入口都没了；`+`（新增会话）又被右对齐，和本该占据右侧的原生操作抢位置。
5. **顶部工具的层级不完整。** 用户希望标签条左边是“标签 + 紧贴的新增会话”，右边才放“原有功能”（模式、子代理等），而不是把 `+` 顶到最右。

---

## Solution

对使用者而言，改动后的界面是：

- 侧栏工作区行有**四态灯**：灰 = 未启用（从没在分屏里打开过）或还没有对话结束；绿 = 有对话真正结束（已启用、非空白、当前空闲）；黄 = 有会话运行中；红 = 有会话等你操作。红 > 黄 > 绿 > 灰。
- 每个工作区行可以**拖动排序**（Host 持久化），行上有一个**删除**入口，点了先弹二次确认，明确说明目录和会话不会被删、运行中的会话不会被停。
- 侧栏 footer 不再有诊断/分屏按钮；设置里出现独立的 **HK Craft** 页，包含诊断信息和“进入/退出分屏”的临时开关。
- 分屏的标签条变成**工具栏**：左边标签，`+` 紧贴最后一个标签；右边是原生功能组，本版提供**当前模式**和**子代理查看**，并给以后的原生工具（如右侧边栏）留位置。
- 模式是只读标签，显示当前窗格会话启动时选的预设；子代理入口显示直接子会话数量，点开可把某个子会话放到新窗格里查看。

## User Stories

### 工作区灯

1. 作为同时维护多个项目的工作区重度用户，我想让从没在分屏里打开过的工作区显示灰灯，这样我一眼能看出哪些工作区真正启用过。
2. 作为分屏用户，我想让“有对话结束、当前空闲”的工作区显示绿灯，这样绿灯只代表真正发生过并结束的对话，而不是“碰巧没有会话在跑”。
3. 作为分屏用户，我想让只有空白新会话、还没发过消息的工作区保持灰灯，这样刚点开一个空工作区不会假装“对话已结束”。
4. 作为分屏用户，我想让有会话正在运行的工作区显示黄灯，这样我能看出后台还在干活。
5. 作为分屏用户，我想让有会话等待我操作（审批、提问、计划确认）的工作区显示红灯，这样我不会错过需要我出手的会话。
6. 作为分屏用户，我想让红灯优先于黄灯和绿灯，这样等待我的工作区永远不会被兄弟工作区的运行状态盖住。
7. 作为分屏用户，我想让黄灯优先于绿灯，这样运行中的工作区不会看起来像空闲。
8. 作为分屏用户，我不想看到“出错”灯：dsh 没有可靠的“上一回合失败”字段，我不希望插件假装知道。
9. 作为分屏用户，我想让已归档会话不参与灯色判断，这样归档的旧会话不会让工作区一直亮红。
10. 作为分屏用户，我想让已不存在的会话被跳过，这样侧栏不会因为目录不同步而崩溃或误亮。
11. 作为分屏用户，我想让灯色在我进入某个工作区分屏后立即从灰变绿/黄/红，不需要刷新页面。
12. 作为使用键盘或读屏的用户，我想让每一行把工作区名和灯色一起读出来（例如“项目 A —— 对话已结束”），这样我不依赖颜色区分状态。
13. 作为新用户，我想在灰灯上看到“未启用/还没有对话结束”的解释，这样我知道灰灯不是故障。

### 删除工作区

14. 作为分屏用户，我想在工作区行上直接看到删除入口，这样不用去别处找。
15. 作为分屏用户，我想在删除前看到二次确认弹窗，这样不会误删工作区。
16. 作为分屏用户，我想让确认弹窗说明“只移除工作区登记，目录和会话不会被删除”，这样我知道数据还在。
17. 作为分屏用户，我想让确认弹窗说明“该工作区的会话仍保留在 dsh 的会话数据里（原生侧栏归入未分组；本插件的精简侧栏不显示未分组）”，这样我知道它们没有被删、也知道去哪儿找。
18. 作为分屏用户，我想让确认弹窗在发现有会话正在运行时明确提示“删除不会停止它们”，这样我不会误以为删除等于中断。
19. 作为分屏用户，我想在确认弹窗里取消（按钮、Escape、点遮罩）后什么都不发生，这样我能安全退出。
20. 作为分屏用户，我想在删除请求进行中看到忙碌状态并禁止重复提交，这样不会发出两次删除。
21. 作为分屏用户，我想在删除失败时看到错误原因且工作区保持原样，这样我能重试或换个做法。
22. 作为分屏用户，我想在删除当前正在看的工作区后自动切到相邻的工作区（没有相邻就切到前一个，再没有就显示空状态），这样我不会停在一个已经不存在的工作区上。
23. 作为分屏用户，我想让被删工作区的窗格布局记录被清掉，这样以后不会因为残留布局而重新冒出一个“已启用”的灰灯工作区。
24. 作为分屏用户，我想让删除工作区**不中断**其中正在运行的会话，这样删除侧栏条目不会误杀后台工作。
25. 作为分屏用户，我想让删除成功后焦点落在下一个工作区行或“添加工作区”上，这样弹窗关闭后我的键盘位置是合理的。
26. 作为分屏用户，我想在只有一个工作区时也能删除它，这样我能清空并重新组织侧栏。

### 拖动排序

27. 作为分屏用户，我想把工作区行拖到另一个工作区上方或下方来调整顺序，这样我能按自己的项目优先级排列。
28. 作为分屏用户，我想在拖动超过一个小阈值后才进入排序状态，这样普通点击不会误触发排序。
29. 作为分屏用户，我想在拖动时看到插入位置指示线，这样我知道会落在哪里。
30. 作为分屏用户，我想把行拖到最后一行的下半部分时追加到末尾，这样不需要额外的“放到底部”区域。
31. 作为分屏用户，我想在拖动被取消或放回原位时什么都不改变，这样不会出现无意义的写入。
32. 作为分屏用户，我想让排序结果在重启 dsh 后仍然保留，因为顺序是 Host 持久化的。
33. 作为分屏用户，我想在排序失败时看到错误并让 Host 恢复的顺序回到界面，这样界面不会显示一个假的顺序。
34. 作为分屏用户，我想让排序不影响当前选中的工作区和焦点，这样我只是调整顺序，不会跳走。
35. 作为分屏用户，我想让删除按钮在拖动时不被触发，这样拖拽不会误删工作区。
36. 作为分屏用户，我想让排序请求进行中时禁止再次拖动，这样并发拖动不会互相覆盖。

### 设置页与临时按钮

37. 作为用户，我不想在侧栏 footer 看到诊断和分屏切换这类开发期按钮，这样侧栏只保留长期功能。
38. 作为用户，我想在设置里看到独立的 **HK Craft** 导航项，这样我知道这个插件的配置和诊断集中在哪儿。
39. 作为用户，我想在 HK Craft 设置页看到客户端是否加载、入口名、`conversation.content` 探测结果和当前是原生视图还是分屏，这样排查安装问题不用打开浮层。
40. 作为用户，我想在 HK Craft 设置页用开关进入/退出分屏，这样在找到长期入口前我仍能使用分屏。
41. 作为用户，我想在分屏切换成功或失败后看到结果（成功关闭设置页，失败显示原因），这样我不会不知道为什么没生效。
42. 作为用户，我想让诊断内容直接排在设置页里，而不是再弹一个浮动面板，这样不会被浮层挡住。
43. 作为中文或英文用户，我想让设置页标题、诊断文案和分屏开关都跟随界面语言。

### 窗格条工具栏

44. 作为分屏用户，我想让新增会话按钮紧贴在最后一个标签后面，这样“标签 + 新开一个”是一组，符合我的点击预期。
45. 作为分屏用户，我想让标签条右侧留给原生功能，而不是被 `+` 占据，这样工具栏能补回对话头部的能力。
46. 作为分屏用户，我想在分屏时看到当前焦点窗格会话的模式（只读），这样我知道这个会话是用哪个 Agent 预设启动的。

52. 作为分屏用户，我想点一个子代理就在新窗格里打开它（已经打开则聚焦），这样我能并排查看父子会话。
53. 作为分屏用户，我想让外部任务行不可导航（与原生一致），这样我不会点进一个不存在本地会话的条目。

56. 作为分屏用户，我想让模式标签和子代理入口在标签很多时不被挤掉，先截断标签，这样右侧原生功能始终可用。
57. 作为分屏用户，我想让子代理列表在打开时刷新一次目录，这样新出现的子会话能及时看到。
58. 作为键盘用户，我想用 Tab 到达子代理入口、Enter/Space 打开、Escape 关闭并回到入口，这样我不依赖鼠标。
59. 作为用户，我不想在本版看到“打开右侧边栏”按钮，因为分屏时上游会把原生右侧边栏藏起来；我宁愿没有按钮，也不要一个点了没反应或偷偷退回原生视图的按钮。

## Implementation Decisions

### 1. 工作区灯：四态，灰灯由“是否启用”决定

- 灯值扩展为 `gray | green | yellow | red`，颜色表增加灰色（中性灰，不跟随主题强调色），四种灯都有本地化名称与说明。
- **未启用 = 该工作区从没在分屏里打开过**：没有已加载的窗格布局，也没有持久化的布局记录。
- 判定顺序：
  1. 未启用 → **灰**（无论它是否有正在运行的原生会话；这是“未启用用灰灯”的直接后果，接受）。
  2. 已启用且任一成员等待用户 → **红**。
  3. 已启用且任一成员运行中 → **黄**。
  4. 已启用且至少一个成员是“已开始”的会话（`blank === false`，即有过至少一条消息）→ **绿**。
  5. 其余（已启用但只有空白/新会话）→ **灰**：绿灯只留给真正结束过对话的工作区。
- 成员过滤保持现状：跳过已归档会话、跳过会话列表里已不存在的会话；工作区快照未就绪时不产生行；会话列表未就绪时无法证明“对话已结束”，因此全部按灰处理。
- 会话信号增加 `started`（来自汇总行的 `blank` 字段），`workspaceLight` 只依赖纯信号，不读 dsh 记录。
- 没有“错误灯”：dsh 的会话汇总与状态映射都没有失败位，读失败需要打开每个会话历史，侧栏不做这件事。
- “启用”判定来源：窗格布局注册表的已加载布局，或持久化布局键是否存在。侧栏工作区区块订阅窗格控制器的快照，进入某个工作区的分屏后灯色立即可变；删除工作区时清掉布局键。
- 在原生视图中打开工作区**不算**启用；只有进入分屏才算。
- 降级：没有窗格控制器或没有传入启用集合时，全部工作区按“已启用”处理，仅按会话推导绿/灰；宁可少一个灰灯，也不要把整列错误地判成未启用。
- 行保持“名称 + 灯 + 当前标记”，当前标记仍由 `mainView` 推导；不新增排序/分组。

### 2. 删除工作区：行内入口 + 二次确认

- 工作区行从单一按钮改为“行容器 + 主选择按钮 + 删除按钮”。主按钮负责打开/切换工作区，删除按钮有独立可访问名；避免按钮嵌套。
- 删除按钮在行悬停或行内焦点时可见；始终存在于 DOM 中，保证读屏可发现。
- 点击删除打开确认对话框：
  - 标题包含工作区显示名（自动名仍按“默认工作区”本地化）。
  - 正文说明保留边界：只移除工作区登记；目录和会话不删除；这些会话仍保留在 dsh 的会话数据里（原生侧栏把它们归入“未分组”，本插件的精简侧栏不显示未分组）。
  - 若该工作区有运行中的会话，追加一行数量提示，并说明删除不会停止它们。
  - 取消 / 删除两个动作；删除进行中显示忙碌并禁止重复提交；失败时在弹窗内显示原因，弹窗不关。
  - Escape、点遮罩、取消都关闭弹窗且不做任何写入；成功后关闭并把焦点还给行列表。
- 执行顺序固定为：先调用公开的 `workspaces.delete(id)`，成功后调用窗格控制器的 `forgetWorkspace(id)`；删除请求失败时不做本地清理。
- `forgetWorkspace` 的职责：
  - 丢弃该工作区的布局记录并清掉持久化布局键；
  - 释放该工作区所有窗格的客户端引用（窗格卸载），**不**中断 Host 上正在运行的会话（与“关闭窗格”不同，删除工作区没有中断语义）；
  - 若删的是当前可见工作区，按 Host 顺序切到下一个工作区；没有下一个则切到前一个；都没有则进入无工作区状态；
  - 发出新的控制器快照，让侧栏和窗格视图同时更新。
- 删除未启用工作区时不产生布局副作用（没有布局可丢）。
- 允许删除最后一个工作区；侧栏保留“添加工作区”入口。
- 不做撤销、不做批量删除、不做目录删除，也不碰会话数据。

### 3. 拖动排序：指针拖动 + Host 持久化

- 排序只改工作区顺序，不改会话顺序（会话顺序已由原生侧栏管理），也不改窗格顺序。
- 交互沿用标签条拖动的心智：指针按下后移动超过 6px 才进入拖动状态；普通点击仍是打开工作区；拖动结束后的那一次 click 被吞掉；删除按钮上的按下不启动拖动。
- 落点计算：指针在目标行上半部 → 插到该行之前；下半部 → 插到该行之后（等价于“插到下一行之前”，最后一行的下半部 → 追加到末尾）。行自身的上下半部都不构成移动时视为无操作。
- 落点逻辑落成纯函数（输入当前 id 顺序、源 id、目标 id、前/后）+ 由适配层调用公开的 `workspaces.insertBefore(sourceId, beforeWorkspaceId)`；`beforeWorkspaceId` 缺省表示追加。
- 不做本地顺序持久化：Host 是顺序真源，服务调用本身会乐观更新并持久化；失败时服务抛出，界面显示错误，Host 的已提交顺序继续作为渲染来源。
- 拖动期间显示插入指示线；拖动源行降低不透明度；排序请求进行中禁止再次拖动。
- 排序不改变当前工作区、焦点或窗格内容。
- 行顺序始终直接来自 `workspaces.list`，侧栏不排序、不缓存顺序。

### 4. 两个临时按钮迁入 HK Craft 设置页

- 删除 `sidebar.footer.action` 的两个注册项（诊断、分屏切换）；插件不再注入该槽。
- 注册 `settings.section` 贡献：固定 id、排在官方分区之后的 order、本地化导航标签“HK Craft”、使用插件自己的 locale 命名空间。
- 设置页内容：
  - **诊断**：客户端已加载、入口名、`conversation.content` 探测状态与消息、当前视图（原生/分屏）。内容直接排版在页面里，不再有浮动面板。
  - **分屏（临时）**：显示当前模式，提供“进入分屏窗格 / 回到原生视图”按钮；按钮读取窗格控制器快照，调用激活/退出；成功后调用设置页的 `close()`，失败显示错误文本。
  - 一段说明：这两个开关是过渡入口，长期入口确定后会移走。
- 设置页不依赖 `configForms` 或任何 settings 数据命名空间，只用槽、locale 和控制器闭包；因此缺少设置服务时只是不注册该页，不影响其他功能。
- 旧诊断浮层的按钮与面板样式移除；共享的 translator/React 惰性加载辅助保留。

### 5. 窗格条工具栏：`+` 贴标签，右侧留给原生功能

- 标签条结构改为三层：
  1. 外层条（固定高度、底边框）；
  2. 可横向滚动的视口：`tablist`（标签项）+ 新增会话按钮，**紧跟在最后一个标签之后**；
  3. 右侧操作组：不参与滚动、不收缩，放在视口之外。
- 新增会话按钮仍是“新开一个窗格（新会话）”，保留原 title/aria/忙碌态；不再右对齐、不再用左边框与标签分隔。
- 右侧操作组按原生头部的相对顺序排列：先当前模式，再子代理入口；以后新增的原生工具继续加在这一组里。
- 标签标题先截断；模式标签限制最大宽度并省略；右侧组永不收缩或被裁掉。
- 标签条只有可见工作区渲染（现状不变）；工作区没有窗格时仍显示空状态，不显示工具栏。
- 右侧组只作用于**焦点窗格**的会话；焦点通过点击标签/窗格切换，控件随快照更新。
- 本版**不提供**“打开右侧边栏”，理由：上游 `rightbar` 只在原生对话面板选中时渲染，分屏面板激活时其“当前会话”为 `undefined`，公开服务无法在分屏内打开原生右侧边栏（已与用户确认）。以后若要补，需要单独立项评估“插件自建右侧面板”或上游新接缝。
- 同样不在本版新增 jobs、open-in-app、schedule、会话日志等原生头部件；右侧组是它们的预留位置。

### 6. 当前模式（只读）

- 数据源：焦点窗格会话在会话汇总里的 `projectionValues.agentPreset`（与原生头部标签同一来源）。
- 名称解析优先级：
  1. Agent 预设名册里该 id 的 `name`（自定义预设自己拥有文案）；
  2. 插件本地化的四个内置预设名（standard / ptc / minimal / cordis）；
  3. 原样 id。
- 名册是可选能力：通过 `ctx.get('remote')` 调 `agentPresets.list()`，成功结果是 `{ ok: true, value: { presets: [{ id, name?, description? }] } }`；读取失败、服务缺失、结果异常都安静降级到本地名或 id，不阻塞渲染。
- 标签只读且不可点击；`title` 用预设描述（若有）或一句“该会话启动时选择的模式”。没有焦点会话或没有 preset 时不渲染。
- 不实现切换：dsh 的会话在首回合后不能换预设，原生头部也只显示不切换。
- 名册在标签条挂载时加载一次，并在焦点会话的 preset id 变化时重试；结果按进程缓存，避免每次焦点切换都发请求。

### 7. 子代理查看

- 数据源：焦点会话在 `sessions.projectionsBySession[sessionId].values.subagentCatalog` 的直接子项（与原生头部触发器同源）；活动状态优先读会话状态映射，退回汇总行的 running。
- 入口显示直接子会话总数与运行中数量；目录不存在或为空时不渲染入口（与原生一致）。
- 打开下拉时调用公开的 `sessions.refreshProjections(parentSessionId)`（若可用）刷新一次；失败忽略。
- 下拉列出直接子项：名字（缺失退回 id）、模式（continuable / one-shot / unknown / external，本地化）、活动状态。外部任务行不可点击（与原生一致）；其余行点击后用窗格控制器的“在新窗格打开会话”路径打开：已在窗格中则聚焦，否则新开窗格。
- 下拉关闭条件：Escape、点外部、选择一项；关闭后焦点回到入口。入口可用 Tab 到达，Enter/Space 打开。
- 本版只做**直接子会话**，不做原生目录的嵌套展开、悬停展开、失败重试、分页与父级面包屑；这些留待后续（原生树是复杂交互，先保证“在分屏里能看到并打开子代理”）。
- 子代理会话在窗格里同样不挂原生的只读 composer（`conversation.composer` 槽不在窗格内），因此 one-shot/父离线子会话的输入限制仍与现有 `/resume` 打开子会话时一致；这是既有缺口，不在本 spec 修。
- 子代理入口与模式标签共用右侧组；两者都只读或只做导航，不写会话状态。

### 8. 上游契约与适配层

新增并记录到 `doc/upstream-contracts.md`：

- `workspaces.delete(workspaceId)`：只移除工作区登记，不删目录与会话；会话回到未分组；失败抛出。
- `workspaces.insertBefore(workspaceId, beforeWorkspaceId?)`：Host 持久化工作区顺序；缺省锚点表示追加；客户端先乐观排序，失败恢复已提交顺序。
- `settings.section`：设置分区槽；注册形如 `{ name, id, order, label, locale }`，组件收到 `close`；导航标签为 thunk，随语言刷新。
- `rightbar` 在 `activePanelId !== null` 时隐藏，`ctx.sidebarRight` 的“当前会话”同时为 `undefined`；这是本版不做右侧边栏按钮的原因。
- `sessions.list` 汇总行的 `projectionValues.agentPreset` 与 `projectionsBySession[*].values.subagentCatalog`（直接子项含 `id`、`mode`、可选 `label`）；`blank` 表示会话是否已开始。
- `remote.agentPresets.list()` 的名册形状；名册读取是可选能力。
- 删除工作区后其窗格布局键需由插件清理，避免“已启用”幽灵记录。

适配层原则不变：dsh 记录形状只出现在适配层；侧栏组件、工具栏组件只消费纯行/纯模型；可选服务在调用时通过 `ctx.get` 读取并在缺失时降级。

### 9. 数据与持久化

- 布局键格式不变；新增“键是否存在”和“清掉键”的存储操作，供“启用”判定与删除清理使用。
- **不新增**插件级排序存储、启用集合存储或设置页状态存储：顺序归 Host，启用状态由布局键推断。
- 删除工作区会清理该工作区的布局键；窗格模式（原生/分屏）仍不跨刷新保持（现状不变）。

### 10. 文案与可访问性

- 新增中英文文案：四态灯名称与说明、删除按钮/弹窗标题/正文/运行提示/忙碌/错误、拖动提示与错误、设置页导航/诊断行/分屏开关/过渡说明、模式标题、子代理入口/列表/模式/活动/空目录说明。
- 四态灯的可读文案定为：灰“未启用 / 还没有对话结束”、绿“对话已结束”、黄“有会话运行中”、红“有会话等你操作”；原名“无活动会话”不再使用。
- `zh` 与 `en` 键集合保持完全一致（现有测试会校验）。
- 删除弹窗使用 `role="dialog"`、`aria-modal`、可访问名；错误用 `role="alert"`；行主按钮的 `aria-label` 含名称与灯色说明。
- 删除入口与子代理入口都有独立可访问名；拖动行提供 title 提示（本版无键盘排序，见“不做的事”）。

## Testing Decisions

### 好测试的标准

只测外部可观察行为：给定纯输入得到纯输出、给定公开服务调用得到可观察的调用序列与状态变化。不测内部字段、不测 JSX 结构、不测私有实现顺序。UI 的最终手感（拖动阈值、指示线、焦点回收）列入手动冒烟清单，不引入 DOM/React 测试环境。

### 接缝（沿用现有、不新增 DOM 接缝）

1. **工作区灯投影（纯函数，现有）**：输入工作区快照、会话列表、状态映射、启用集合，输出行数组。
2. **工作区排序落点（新纯函数）**：输入 id 顺序、源、目标、前/后，输出 `{ beforeId? }` 或“无操作”。
3. **工作区适配层（现有，假 ctx）**：删除、排序、启用集合投影。
4. **布局存储与窗格控制器（现有，假服务 + 内存存储）**：布局键存在/清理、删除工作区的布局与引用处理、相邻工作区切换。
5. **窗格工具栏投影（新纯函数）**：焦点会话、模式 id、子代理行/计数/可见性。
6. **预设名解析（新纯函数 + 名册适配）**：名册名 > 本地内置名 > id；名册失败降级。
7. **插件入口注册（现有，假 ctx）**：设置分区注册、footer 注册消失、注入回调集合。

### 具体覆盖

- 灯：四态各一例；红 > 黄 > 绿 > 灰的优先级；未启用即使有运行/等待也是灰；已启用但只有空白会话是灰；已启用且有非空白空闲会话是绿；归档成员不参与；未知会话跳过；工作区快照未就绪无行；会话列表未就绪全灰；空启用集合全灰；缺省启用集合的降级语义（全部视为已启用，按会话推导绿/灰）。
- 排序纯函数：向前/向后移动、插到前/后、追加到末尾、放回原位、源=目标、未知 id、空列表、单元素列表。
- 适配层：删除先调服务再调窗格清理、服务失败时不清理、错误向上抛；排序把前/后换算成正确的 `beforeWorkspaceId`（含追加的 `undefined`）、失败上抛；启用集合传入投影。
- 存储：键存在检测在缺失/空存储/异常存储下安全；清理在缺失 `removeItem` 时返回失败而不抛。
- 控制器：删除已加载工作区会丢布局、清键、释放引用、不中断会话；删除当前工作区切到下一个/上一个/无；删除未加载工作区只清键；删除后快照更新；未知 id 无操作。
- 工具栏投影：无焦点会话时无模式/子代理；有 preset 时带出 id；自定义/内置/未知名的解析；目录缺失/为空时入口隐藏；计数与运行中计数；活动状态来自状态映射并有汇总行回退；外部行标记不可导航。
- 预设名适配：名册成功、名册失败、名册缺失、结果畸形；名册与名字解析失败时仍渲染出可读标签。
- 入口注册：不再注册 `sidebar.footer.action`；注册 `settings.section`（id、order、label、locale、组件是函数）；工作区槽注入新增回调；设置页组件工厂可创建。

### Prior art

沿用现有单测风格：工作区灯纯函数测试、窗格条投影测试、工作区适配层假 ctx 测试、窗格控制器/布局恢复的假服务集成测试、插件入口注册测试。新的排序纯函数与工具栏投影按同样的结构组织。

### 手动冒烟（构建 + 安装后）

- 侧栏灯：未启用灰、进入分屏后按状态变化、归档会话不影响。
- 删除：悬停/键盘聚焦出按钮、确认弹窗文案、Escape/遮罩取消、删除当前工作区后的切换、失败提示、运行中会话不被中断。
- 排序：6px 阈值、插入线、上/下半部落点、追加末尾、重启后顺序保留、失败恢复。
- 设置：footer 不再有按钮、HK Craft 页出现、诊断信息正确、进入/退出分屏后设置页关闭、错误可见。
- 工具栏：`+` 紧跟标签、窄宽度时标签先截断、模式随焦点切换、名册缺失时退回本地名/id、子代理入口显隐与计数、下拉可用键盘关闭、点外部关闭、子项在新窗格打开、外部行不可点。
- 回归：`pnpm build` → `pnpm check` → `pnpm test`；安装 → 重启 dsh → 冒烟 → 卸载不残留。

## Out of Scope

- **分屏内的原生右侧边栏**：上游在分屏面板激活时隐藏右侧边栏且没有公开的“指定会话展开”接口；本版不做该按钮，也不自建右侧面板。
- 原生对话头部的其他工具：jobs、open-in-app、schedule、会话日志、视图 More 菜单等；右侧操作组为将来预留。
- 子代理目录的嵌套展开、悬停展开、失败重试、父级面包屑、把子代理开进右侧边栏；本版只看直接子会话并在窗格打开。
- 子代理会话在窗格里的只读 composer/续聊限制（既有缺口）。
- 工作区重命名、删除撤销、批量删除、目录删除、会话删除或归档。
- 工作区排序的键盘替代（Alt+↑/↓ 等）；本版只做指针拖动。
- 窗格标签之间的排序（现有拖动交换已存在，不在本 spec 内）。
- 分屏模式的跨重启保持；本版仍由设置页临时开关进入。
- 新增第三方依赖、修改 dsh 上游代码、引入 DOM/React 组件测试框架。
- 除中英文外的其他语言文案。

## Further Notes

1. **灰灯的边界**：用户确认“未启用”按“从没在分屏里打开过”判定。为满足“只有真正有对话结束才绿灯”，已启用但只有空白会话的工作区也用灰；也就是说灰同时表示“未启用”和“已启用但还没有结束过对话”。这是两条要求叠加后的唯一自洽解，若后续想要第五种状态，再单独讨论。
2. **绿灯的局限**：`blank === false` + 空闲能证明“对话已开始且当前没有回合在跑”，但 dsh 没有“上一回合成功/失败”字段；失败结束的回合也会是绿。这是上游数据限制，不假装知道。
3. **灰灯与原生运行**：从未进过分屏的工作区即使有原生会话在跑也显示灰。这是“未启用用灰灯”的直接后果；如果实际使用中觉得丢信息，可以再讨论“未启用但运行中”的特殊表达。
4. **删除不中断**：与“关闭窗格会中断当前回合”刻意不同。删除工作区只是移除登记；Host 上的会话继续跑，侧栏会话之后出现在未分组。确认弹窗必须写清这一点。
5. **未分组在精简侧栏里不可见**：dsh 把被删工作区的会话归入未分组，但本插件的侧栏只渲染工作区行，不渲染未分组。因此文案只承诺“会话保留在 dsh 中”，不承诺“在本侧栏还能看到”。若要恢复可见性，需要另开一个“未分组”分组，不在本 spec 内。
6. **右侧边栏的上游事实**：`rightbar` 只在 `activePanelId === null` 时 `visible`，`ctx.sidebarRight` 的 mounted 会话在分屏时被置空；本版据此不做按钮。已记录到上游契约页，未来若上游提供“指定会话展开”或允许在分屏内渲染右侧栏，再补。
7. **子代理简化**：本版用与原生相同的数据源，但只复刻直接子项列表。原生目录树的复杂度（嵌套、悬停、失败重试、只读 composer）不搬；这样能在不复制上游 UI 的前提下补回入口。
8. **临时功能的家**：HK Craft 设置页是诊断与分屏开关的过渡归宿。分屏长期入口（默认分屏、快捷键或侧栏入口）确定后，这两个控件应迁走或删除，设置页保留诊断也可。
9. **ADR 与文档**：实现完成后建议追加一条 ADR，记录“侧栏工作区管理回到插件侧栏（四态灯 + 删除 + 拖动排序）”“窗格条承载原生头部能力，右侧边栏受上游限制暂缓”；ADR-0005 关于“只保留名称 + 三态灯 + 添加工作区”的表述由新条目取代，旧条目不改写。`doc/upstream-contracts.md` 按“实现决策 8”补充契约。`GLOSSARY.md` 可补“窗格条工具栏”与“启用（工作区）”两个词。
10. **验收门槛**：`pnpm build` → `pnpm check` → `pnpm test` 全绿；desktop 实机安装、重启、冒烟、卸载无残留。
