# 03: 删除工作区与二次确认

**What to build:** 每个工作区行提供删除入口，点击后先弹二次确认。确认框要讲清保留边界：只移除工作区登记，目录和会话不会被删除，会话仍保留在 dsh 里（原生侧栏把它们归入未分组，本插件的精简侧栏不显示未分组）；如果该工作区有会话正在运行，还要说明删除不会停止它们。确认后删除工作区登记，并让分屏控制器丢弃它的布局、清掉持久化布局键、释放窗格引用、按 Host 顺序切到相邻工作区；正在运行的 Host 会话不被中断。

**Blocked by:** 01 — 侧栏工作区行结构预重构

**Status:** resolved

- [ ] 行内删除入口在行悬停或行内键盘焦点时可见，有独立可访问名，且不会误触发打开工作区。
- [ ] 确认弹窗包含工作区显示名、保留边界说明，以及（有运行中会话时）数量提示和“删除不会停止它们”的说明。
- [ ] 取消按钮、Escape、点击遮罩都关闭弹窗且不写入；删除进行中显示忙碌并禁止重复提交；失败时在弹窗内显示原因并保留工作区。
- [ ] 确认后先调用公开的工作区删除能力；成功后丢弃该工作区的布局、清掉持久化布局键、释放其窗格引用，并发出新的控制器快照。
- [ ] 删除的是当前可见工作区时，按 Host 顺序切到下一个；没有下一个则切到前一个；都没有则进入无工作区状态。
- [ ] 删除工作区不中断正在运行的会话，也不删除目录或会话数据。
- [ ] 删除未启用工作区时不产生布局副作用；允许删除最后一个工作区，侧栏仍保留“添加工作区”。
- [ ] 删除成功后焦点落在下一个工作区行或“添加工作区”上。
- [ ] 弹窗使用 `role="dialog"`、`aria-modal` 和可访问名；错误使用 `role="alert"`。
- [ ] 单元测试覆盖：删除服务失败时不清理、删除当前/非当前工作区、相邻工作区切换、布局键清理、引用释放、未知工作区无操作。
- [ ] 上游契约页记录删除语义：只移除登记、不删目录与会话、失败抛出。
